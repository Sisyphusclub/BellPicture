# 修复生图页路由返回后历史消失

## Goal

修复用户离开 `/generate` 后再从应用导航返回时，已生成的当前会话结果在主内容区消失的问题，确保路由往返不会让用户误以为历史记录丢失。

## Requirements

- 从其他页面普通导航回到不带查询参数的 `/generate` 时，自动恢复当前账号在本标签页最后查看的生成会话。
- 使用 `replace` 写回 `session` 查询参数，避免增加无意义的浏览器历史记录。
- 带提示词、设置或参考图查询参数的创作入口不得被旧会话恢复逻辑截获。
- 带 `autoGenerate` 路由状态的自动生成入口不得被旧会话恢复逻辑截获。
- 没有已有会话时继续显示空白创作状态。
- 裸路由只在首次进入时判定一次，不因其他标签页后续更新会话 store 而突然跳转。
- 最后会话指针按用户隔离，不自动恢复另一账号留下的会话。
- 不改变后端历史 API、账号隔离、删除或生成任务语义。

## Acceptance Criteria

- [x] 从生图页切换到其他路由，再通过导航返回生图页后，最近会话的结果重新显示。
- [x] 恢复时 URL 包含有效的 `session` 查询参数。
- [x] 没有会话时访问 `/generate` 仍显示空白创作状态。
- [x] 带查询参数或 `autoGenerate` 状态的创作入口保持现有行为。
- [x] 多会话时恢复刚离开的会话，而不是固定恢复 store 首项。
- [x] 进入裸路由后发生的会话 store 更新不会触发迟到的自动恢复。
- [x] 相关路由测试、TypeScript、Lint、全量测试、生产构建、格式及 `git diff --check` 通过。

## Technical Notes

- 会话及批次 ID 由 `useGenerationSessions` 的外部 store 持久化。
- 后端历史批次由用户隔离的 `useImageHistory` store 恢复。
- 主结果流由 URL 中的 `session` 参数选择；导航项使用裸路径 `/generate`，因此返回时需要恢复最近会话身份。
- 回归测试必须经过真实路由切换，并使用持久化批次重建结果，不能依赖组件卸载前的本地 state。

## Out of Scope

- 重设计历史面板或新增会话管理界面。
- 修改生成记录的后端持久化格式。
- 恢复页面卸载后已取消的瞬时请求状态。
