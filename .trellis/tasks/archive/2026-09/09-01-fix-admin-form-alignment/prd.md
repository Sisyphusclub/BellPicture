# 修复用户管理表单列错位

## Goal

修复用户管理页 Data Table 中表头与数据行的列边界不一致问题，让“用户、创建时间、今日额度、操作”四列在桌面端共享同一套列轨道，额度输入与保存/删除按钮保持垂直、水平对齐；移动端继续使用现有的响应式记录布局。

## Requirements

- 表头和每条用户记录必须使用相同的桌面列轨道，不能由各自内容独立计算宽度。
- “今日额度”列中的输入框、额度摘要和进度条保持在同一列内，不挤压“操作”列。
- “操作”列为稳定的按钮组宽度，表头标题与按钮组右边界对齐。
- 保留现有 beUI `Button`、`Input`、Data Table 结构、hover 样式和交互行为。
- `max-width: 1180px` 的移动/平板记录布局和 `max-width: 560px` 的单列布局不回归。

## Acceptance Criteria

- [x] 1440px 桌面视口下，表头与数据行四列左边界一致。
- [x] 用户管理页操作按钮不再导致前面列向左偏移或额度输入错位。
- [x] 1180px 以下表头隐藏、记录布局保持可读且无横向溢出。
- [x] 390px 移动视口下表单和操作按钮不溢出，按钮组仍可用。
- [x] 增加或更新布局回归测试，覆盖稳定列轨道与响应式行为。
- [x] 类型检查、lint、全量测试、构建、格式和空白检查通过。

## Definition of Done

- 代码与测试形成独立提交。
- 相关前端规范或布局契约记录本次列轨道修复经验。
- Trellis 任务归档并记录会话。

## Technical Approach

为 `.admin-table` 建立统一的桌面列轨道，并让 `.admin-row` 使用 `grid-template-columns: subgrid`（配合明确的列定义）或等价的共享轨道方案；操作列预留按钮组所需的固定最小宽度。保留现有断点下对 `.admin-row` 的覆盖，让移动端继续由 `data-label` 呈现字段标签。

## Out of Scope

- 不重做用户管理页视觉风格或表格组件。
- 不修改额度 API、用户数据、权限逻辑或通知行为。
- 不改变现有 hover、按钮语义和移动端交互。

## Technical Notes

- 页面：`frontend/src/views/AdminUsersView.tsx`。
- 主要样式：`frontend/src/styles/base.css` 中 `.admin-page .admin-table`、`.admin-row`、`.admin-actions`。
- 现象来源：表头和数据行都是独立 Grid；数据行的按钮内容把最后一列撑到约 177px，而表头最后一列仅约 20px，导致前三列边界不一致。
- 视觉参考：用户提供的用户管理页截图；产品 Data Table 组件映射记录在 `design.md`。
- 浏览器验证：`1440 × 813` 下表头和数据行列轨道一致、横向溢出为 `0`；`390 × 844` 下表头按断点隐藏、记录切换为单列且无横向溢出。
