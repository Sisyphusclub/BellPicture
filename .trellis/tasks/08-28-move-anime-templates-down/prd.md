# 创作模板动漫内容后置

## Goal

让创作模板页与发现页采用一致的内容优先级：默认“精选排序”先展示通用创作模板，再展示“动漫漫画”分类模板，避免动漫内容占据首屏。

## Requirements

- 创作模板页默认“精选排序”中，非动漫模板在前，“动漫漫画”分类模板稳定后置。
- 复用发现页的同一条分类排序规则，不通过标题或英文提示词关键字猜测内容类型。
- 各分组内部保持原始导入顺序。
- 分类、搜索和收藏筛选继续在当前结果集上工作。
- 用户显式选择“最近使用”或“名称排序”时，尊重该排序，不额外强制动漫后置。
- 发现页现有动漫后置行为保持不变。

## Acceptance Criteria

- [x] 创作模板默认首批卡片不属于“动漫漫画”，动漫模板位于列表尾部。
- [x] 默认排序仍展示全部 163 个模板且图片 URL 唯一。
- [x] “动漫漫画”分类仍展示全部 12 个动漫模板。
- [x] “名称排序”和“最近使用”保持原有语义。
- [x] 发现页首批非动漫、尾部包含动漫的既有测试继续通过。
- [x] 组件来源检查、类型检查、lint、相关测试、构建和本任务文件格式检查通过。

## Definition of Done

- 排序逻辑由共享数据模块统一提供。
- 模板页和发现页调用共享逻辑。
- 路由回归测试覆盖默认顺序及显式排序。
- 改动以独立中文规范提交到 Git。

## Technical Approach

在 `creationTemplates.ts` 导出纯函数，将输入模板复制后按 `category === '动漫漫画'` 的布尔优先级稳定排序。`LandingView` 使用该函数替代页内比较器；`TemplatesView` 仅在 `featured` 分支使用该函数，`recent` 和 `title` 分支保持现有逻辑。

## Decision (ADR-lite)

**Context**: 发现页已经按分类后置动漫模板，但模板页直接使用按导入顺序排列的共享清单，导致两页首屏内容优先级不一致。

**Decision**: 在共享数据层提供稳定排序函数，两个消费页面复用；显式用户排序优先于内容优先级。

**Consequences**: 两页默认顺序一致，分类判断集中；未来若分类名称或优先级变化只需修改一处。名称和最近使用排序不会被隐式二次排序破坏。

## Out of Scope

- 不修改 163 个模板的数据内容、图片、提示词或分类。
- 不改变创作模板卡片布局、工具栏样式或详情弹窗。
- 不将“复古赛博”“电影动画”等含动漫风格字样的其他分类自动归入动漫。
