# 修复安全竞态与资源风险

## Goal

修复源码评审确认的 12 个安全性、并发一致性、隐私和资源管理缺陷，使跨用户数据隔离、付费额度、取消语义、公开接口和文件/媒体传输在并发及故障场景下保持正确。

## Requirements

* 参考图上传记录所属用户，生成前只允许当前用户复用自己的上传；公开历史响应不得泄露可复用的参考图标识。
* 用户额度在供应商调用前以数据库事务原子预留，成功后提交，供应商失败或请求取消时释放；并发请求不得超额调用供应商。
* 前端历史缓存以用户 ID 和请求代次隔离，账号切换后丢弃旧账号的迟到响应。
* 浏览器中止生成后，服务端中止供应商请求，并跳过额度提交、输出持久化、演示缓存和历史写入。
* 演示提示词缓存是尽力而为的派生数据，缓存失败只记录日志，不改变已完成生成的响应。
* 输出文件读取仅将 `ENOENT` 映射为 404，其他存储故障返回 500；响应使用文件流和背压，不整文件读入内存。
* 供应商日志只记录提示词长度、模型、请求标识等元数据，不记录提示词内容预览。
* Nginx 上传请求上限为后端默认单文件上限预留 multipart 开销，并提供与部署配置同步的明确方式。
* 媒体代理设置明确超时，并在客户端断开时取消上游请求和管道。
* 公开历史使用有最大页大小的游标分页，并增加 `(is_public, created_at, id)` 查询索引；前端画廊按分页响应消费。
* 删除未生效的 `GPT_POOL_QUOTA` 配置、Compose/README 暴露和相关测试，避免虚假的成本保护承诺。

## Acceptance Criteria

* [ ] 用户 B 使用用户 A 的参考图 ID 时在供应商调用前收到拒绝；用户 A 仍可正常复用自己的参考图。
* [ ] 仅剩 1 个额度时并发提交两个单图请求，最多一个请求进入供应商；失败/取消后额度恢复。
* [ ] A 的历史请求迟于 B 返回时不会覆盖 B 的缓存，注销后缓存立即清空。
* [ ] 客户端断开会触发供应商 `AbortSignal`，取消任务不扣额度、不写历史、不继续演示缓存。
* [ ] 演示缓存写入失败仍返回生成结果并写入历史。
* [ ] 输出不存在返回 404，权限/I/O 错误返回 500；大文件通过可取消的流式响应返回。
* [ ] 生图日志中不包含 `promptPreview` 或任何提示词片段。
* [ ] 默认 10 MiB 文件加 multipart 开销能通过代理；自定义上限有文档化的同步配置入口。
* [ ] 媒体上游超时和下游断开均会取消上游 fetch。
* [ ] 公开历史单页不超过上限，可通过游标稳定遍历，并命中复合索引。
* [ ] `GPT_POOL_QUOTA` 不再出现在运行时配置、部署示例和文档中。
* [ ] 后端、前端新增边界测试通过，现有 lint、类型检查和测试套件保持通过。

## Definition of Done

* 数据库 schema 与 SQL migration 同步，已有部署可前向迁移。
* API 类型、服务实现、控制器、前端消费者和部署文档保持一致。
* 关键竞态、权限、取消、错误映射、分页和配置边界均有自动化测试。
* 每一批相关修改独立提交，不夹带工作区原有的生成页样式改动。

## Technical Approach

* 新增参考图元数据表，以文件名为主键并关联上传用户；上传落盘后写元数据，生成服务接收 `userId` 并查询所有权。
* 将 `QuotaPool` 改为预留票据接口；SQLite 事务内读写 `used_today` 完成原子预留，票据只允许提交或释放一次。现有 `used_today` 表示已消费和在途预留之和，释放时事务递减。
* 控制器从请求/响应关闭事件构造 `AbortController`，把信号传给编排服务和 provider；在每个不可逆阶段前检查中止状态。
* 输出存储暴露经过路径校验的 stat/stream 能力，并保留底层错误作为 `AppError.cause` 供控制器精确映射。
* 公开历史使用 `(created_at, id)` 复合游标稳定翻页；响应包含 `records` 与可选 `nextCursor`，前端类型守卫兼容该结构。
* 删除无运行时消费者的 `GPT_POOL_QUOTA`，不在本轮引入新的全局额度产品语义。

## Decision (ADR-lite)

**Context**: 修复涉及付费调用、数据库状态与客户端生命周期，单纯在现有只读检查后补异常处理仍会保留竞态和孤儿副作用。

**Decision**: 采用持久化所有权、事务预留票据、端到端 AbortSignal、稳定游标分页和流式 I/O；选择移除无效全局额度配置而不是在缺少产品定义时新增额度池。

**Consequences**: 需要新增迁移并调整若干服务接口与测试替身；换取跨进程/并发下可证明的数据隔离与额度正确性。请求在供应商已完成但服务端尚未提交时被取消，输出清理由 provider/编排层负责，额度会释放。

## Out of Scope

* 不新增全局 GPT 账号池或后台额度管理产品功能。
* 不重构生成页视觉样式、历史页信息架构或认证系统。
* 不改变私有历史的产品展示与元数据编辑能力，除非为账号隔离所必需。
