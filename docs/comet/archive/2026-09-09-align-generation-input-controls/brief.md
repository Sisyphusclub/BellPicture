# 目标

统一发现页与生图页的生图输入框，让用户可直接选择生图模型，并通过一个“自定义”入口集中设置画面比例、生成张数和清晰度。

# 范围

- 发现页和生图页使用一致的输入框视觉语言、模型选择方式及参数入口。
- 两个页面提供 `gpt-image-2`、`gpt-image-2.5-flare`、`gpt-image-2.5-sunburst` 三个模型，并保持 `gpt-image-2` 为默认模型。
- 输入框工具栏直接显示模型选择和“自定义”入口；画面比例、张数、清晰度收纳在自定义面板中。
- 自定义面板使用项目现有 Beui 组件，并在桌面端横向排列参数控件；窄屏下允许有序换行，不产生横向溢出。
- 画面比例按“智能、1:1、3:4、4:3、16:9、9:16、2:3、3:2”的顺序提供。
- 生成张数可选择 1 至 4 张；清晰度可选择 1K、2K、4K。
- 所选模型、解析后的画面比例、张数和清晰度贯通发现页到生图页的交接、生成请求、任务状态、历史记录及完整设置复用。
- 新增 3:4、4:3 的前后端类型、校验、尺寸映射与测试覆盖。
- 2K、4K 对所有已登录用户开放，继续通过现有高分辨率服务和额度池生成。
- 保持“发布到发现”和额度/调用状态在输入框工具栏中，不收进自定义参数面板。

# 非目标

- 不新增第四个生图模型，不改变三个模型的精确上游标识和默认值。
- 不新增独立供应商、API Key 类型或模型路由协议。
- 不改变现有按生成张数扣减额度的规则，也不为不同清晰度新增价格档位。
- 不改变参考图数量上限、历史分组、收藏、下载和删除等生图结果功能。
- 不重做发现页画廊、生图会话列表或页面导航。

# 验收示例

- A1：发现页和生图页输入框具有一致的外框、输入区、工具栏、模型选择及“自定义”入口样式。
- A2：两个页面的模型选择器均显示三个指定模型，默认选择 `gpt-image-2`，切换后提交值与所选标识一致。
- A3：打开“自定义”后，比例、张数和清晰度使用 Beui 组件横向排列；关闭后设置仍保留，工具栏不平铺这些参数控件。
- A4：比例列表按指定顺序完整显示，包含新增的 3:4、4:3；“智能”按第一张可读取的参考图匹配最接近比例，无参考图时解析为 1:1。
- A5：张数只能选择 1 至 4；所有已登录用户均可选择并成功提交 1K、2K、4K，不因非管理员身份收到高分辨率权限错误。
- A6：选择 4K 时，若当前为“智能”或其他不兼容比例则自动切换到 16:9；4K 状态下仅 16:9、9:16 可用。
- A7：从发现页带设置发起生成时，生图页与实际生成请求保留模型、解析后比例、张数、清晰度和公开范围；历史完整设置复用后再次提交也保持一致。
- A8：后端接受 1K、2K 的 3:4、4:3 请求并向上游发送对应尺寸；4K 的 3:4、4:3 仍在上游调用前被拒绝。
- A9：在 1440、900 和 390 像素宽视口打开或操作模型/自定义下拉层时，页面没有横向跳动、控件重叠或文本溢出。

# 约束与不变量

- UI 优先复用项目现有 Beui `AnimatedDropdown`、`MorphPopover`、`SelectMenu`、`Button`、`Switch` 等组件，不引入第二套组件库。
- 生成张数继续遵守现有最小 1、最大 4 的服务端边界。
- 4K 继续只提供 16:9 和 9:16 两种尺寸映射；服务端继续拒绝其他 4K 比例，前端必须先阻止或归一无效组合。
- 所有清晰度继续要求用户登录；开放 2K/4K 不开放匿名生图。
- “智能”是前端选择状态，提交前必须解析成后端支持的具体比例；第一张参考图尺寸不可读取时按无参考图处理并解析为 1:1。
- 本 change 依赖 `add-image-model-upstreams` 的三个模型协议和状态持久化实现；进入 Build 前必须与其最终目标分支对齐。
- 下拉层打开时不得通过修改页面滚动条占位造成页面横向位移。

# 决策

- “其他的功能放到自定义中”按用户列举范围解释为画面比例、张数、清晰度三项；模型选择保留为工具栏一级控件。
- “发布到发现”和额度/调用状态继续作为工具栏快捷状态，不纳入参数面板。
- 自定义面板在桌面端采用单行横向布局，移动端按可用宽度换行，以可操作和不溢出优先。
- 两页复用同一套生成参数控件和样式契约，避免分别维护后再次产生视觉偏差。
- 2K、4K 对所有已登录用户开放，移除高分辨率路由的管理员限制，保留登录校验和现有额度扣减方式。
- 4K 保持仅支持 16:9、9:16；用户切换到 4K 时，如当前比例不兼容则自动切换为 16:9，其他比例在 4K 状态下不可选择。
- “智能”使用第一张可读取参考图的宽高比匹配最接近的受支持比例；没有可读取参考图时使用 1:1。
- 3:4、4:3 支持 1K 和 2K，不扩展到 4K。

- 运行前后端类型检查、lint 和生产构建。

- 使用实际请求桩验证模型、比例、张数、清晰度及公开范围的最终请求载荷。
