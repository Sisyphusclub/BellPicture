# 目标

让生图用户可以在现有 `gpt-image-2` 之外选择上游已提供的 `gpt-image-2.5-flare` 和 `gpt-image-2.5-sunburst`，并把选择准确传递到生成请求。

# 范围

- 在生图工作区提供 `gpt-image-2`、`gpt-image-2.5-flare`、`gpt-image-2.5-sunburst` 三个模型选项。
- 保持 `gpt-image-2` 为新会话默认模型。
- 将当前选择写入生成请求、任务设置和生成历史；复用完整设置时恢复原模型。
- 在 OpenAI 兼容的 `/v1/models` 响应中公开两个新模型标识。
- 更新覆盖模型选择、请求透传、设置复用和兼容模型清单的自动化测试。

# 非目标

- 不新增供应商协议、API Key 或独立上游地址配置。
- 不改变计费、额度、清晰度、画面比例、参考图或公开范围行为。
- 不改变现有 `gpt-image-2` 默认值，也不重写已有历史记录。
- 不为三个模型设置不同的参数、价格或能力说明。

# 验收示例

- A1：打开生图工作区时，模型选择器显示 `gpt-image-2`、`gpt-image-2.5-flare`、`gpt-image-2.5-sunburst`，且默认选中 `gpt-image-2`。
- A2：用户选择 `gpt-image-2.5-flare` 或 `gpt-image-2.5-sunburst` 后提交生成，前端请求中的 `model` 与所选标识完全一致，生成任务与历史设置保留该标识。
- A3：用户对使用新模型生成的批次执行“复用完整设置”时，生图工作区恢复该批次的模型选择，后续再次生成继续使用该模型。
- A4：携带有效鉴权请求 `/v1/models` 时，响应模型列表包含 `gpt-image-2.5-flare` 和 `gpt-image-2.5-sunburst`，并保留原有模型。

# 约束与不变量

- 模型标识必须使用用户给出的精确字符串，不做别名转换。
- 所选模型继续通过现有生成接口和 `TwoApiImageProvider` 透传，不引入新的分发服务。
- 现有未提交文件和其他 active change 的内容不得混入本 change 的实现提交。

# 决策

- 沿用当前目录和当前分支处理本 change，这是用户明确选择的工作区方式。
- 现有 `gpt-image-2` 保持默认；两个新上游作为并列可选模型加入。
- 同步更新用户生图入口和 OpenAI 兼容模型发现接口，避免可选择模型与公开模型清单不一致。

# 待解决问题

无。
